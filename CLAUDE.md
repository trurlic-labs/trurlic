## Trurlic

Architecture layer for AI-assisted codebases. Typed decision graph stored in `.trurlic/` as one TOML file per node, served to coding agents over MCP: the decisions and project-wide rules that constrain a component or a file before code is written, with proposed decisions marked until the owner accepts them.

Named after Trurl (Stanisław Lem, *The Cyberiad*) — the constructor who thinks deeply about what he builds before building it.

### Architecture

Single crate, eleven modules (`src/lib.rs`). Visibility enforces boundaries — `pub(crate)` on everything except `cli` and `store`.

```
store       → git                         Decision graph: TOML node files, their
                                          canonical form, validation, the
                                          quality bar of a write, atomic
                                          writes, file locking, migrations, and
                                          a shared graph's history commits
mcp         → store, budget, discovery    MCP server: JSON-RPC stdio, version
                                          negotiation, the server's own requests,
                                          argument and result specs, the `apply`
                                          and `status` tools and their CLI twins
                                          (`mcp::twin`), tool dispatch, context
                                          assembly, the 24 KiB cap on every tool
                                          result
commands    → store, mcp, git, discovery  CLI command handlers: init, apply,
                                          status, query, check, fmt, migrate,
                                          install (registers the MCP server with
                                          Claude Code), and the `serve` entry
                                          point
cli         → commands, store             clap definitions and dispatch; an
                                          argument names a store type
                                          (`Placement`)
budget      → (no internal deps)          Fitting output into a byte budget: the
                                          level search behind the result cap
error       → store (types)               The crate's `Error` enum and `Result`
                                          alias; it names the store's anchor-fault,
                                          timestamp-fault, placement-doubt and
                                          refusal types
console     → (no internal deps)          Terminal I/O: `out!` to stdout, `diag!`
                                          to stderr
git         → (no internal deps)          The `git` command line as a child
                                          process: one typed function per
                                          question (tracked, ignored, toplevel,
                                          common dir, worktree list), `-z`
                                          output, the variables that redirect
                                          git cleared; and `git::graph`, the
                                          graph's own repository: create,
                                          status, stage, blobs, commit
discovery   → store, git                  Finding the graph and the code root
                                          from the directory a call starts in
code        → store (types)               The code index, pure: each source
                                          file's definitions with their spans
                                          and span hashes (tree-sitter for
                                          Rust, lexical resolvers for TOML,
                                          JSON, Makefiles and Markdown), the
                                          symbol grammar, macro expansion over
                                          a crate, and what an anchor names
sources     → code, store                 The shell around the index: the walk
                                          of the code root, bounded reads, the
                                          index's cache, and the anchors of a
                                          graph resolved
```

Every module but `code` uses `error` and `console`; the arrows leave them out.

**store** is the foundation. It imports no other module except `error`, `console` and `git`, which it uses for a shared graph's own repository alone (`store/history.rs`). Every write to a current-format graph is a method of the `Writer` that `Store::begin_write` returns (`init` and `migrate`, which write before one exists, take the lock themselves), which owns the exclusive lock and the graph loaded under it; the commit path takes `&StoreLock` as proof of the lock. `store::text` is the one home of the rules for every text a graph file holds and a write takes, so what a reader sees is what an agent is held to: validation holds every decision's and component's text to it, whoever wrote it, a hand edit included; a write is also held to the quality bar (`store::quality`), which no validation reports.

**error** carries the path of the file behind every I/O and TOML failure (`Error::Io`, `Error::Toml`); nothing converts a bare `io::Error` into it, so a `?` cannot drop the path. A batch the store refuses is `Error::Refused` with its typed `store::Refusal`, and a path the store derived that breaks its own layout `Error::StorePath` with its typed fault. `commands::install` returns its own `InstallError`, which wraps `Error`, and the CLI twins of the tools (`apply`, `status`) return the tool's own `ToolError`, so a command refuses as the call does; `cli` prints each as `error: <message>` with exit status 1.

**mcp** never writes to the graph directly: `apply`, the one write tool, hands its parsed batch to `Writer::apply`, which holds every rule, and the server holds no graph between calls. A tool is built on a spec (`mcp::spec`): its `Args::declare` is walked once for the `inputSchema` and once per call for the parse, and its result type's `Output::declare` once for the `outputSchema` and once per call for the JSON, so neither schema can drift from the code, and an unknown key, a wrong type or a broken limit is refused naming the field. Its `Access` (read, write, interactive) decides the lock the call takes. A result is `structuredContent` and the same JSON as text. Every refusal, a missing store included, is a tool result with `isError: true` whose text is `{"error": {"kind", "field"?, "op"?, "rule"?, "message"}}` (`mcp::result`); a refused batch is `batch_refused`, naming its op (`{index, op, name}`), the argument (`ops[3].add_tags[0]`) and the rule. A JSON-RPC error answers only a malformed message, an unknown method or tool, or a panic. `tools/list` is the spec-built tools (`spec::TOOLS`: `apply`, `status`), then the two tools that predate specs, `get_context` and `get_decisions_for_file`, which keep their hand-written schemas in `mcp::tools` and return text only until `brief` replaces them. `apply`'s result lists, per op and for the batch's `origin`, the first `MAX_WARNINGS_PER_OP` warnings (`{field, rule, pattern, at}`: the argument, the pattern's index, the match's offset), counts the rest (`Done::more_warnings`, `more_origin_warnings`) and carries each named pattern's message once (`patterns`), so a full batch's result fits the budget whatever its warnings (the arithmetic is beside `the_longest_result_of_a_full_batch_fits_the_budget`). A result built on a spec is fitted once (`truncate::fit_value`): its text is the serialization of the value sent as `structuredContent`. `status` reports what the graph's files and a shared graph's own history hold (issues, history findings, each component's decisions, and the counts of the rules `[quality]` sets), each section fitted to the budget by `budget::level` with what it leaves out counted; where the graph sits in the project's git is `check`'s. No request names the agent's session (stdio carries none; `clientInfo` names the client program), so `apply`'s history commit carries no `Session:` trailer.

**mcp transport**: `initialize` answers the client's protocol revision when it is in `PROTOCOL_VERSIONS`, else the latest, and keeps the client's capabilities. During a tool call a handler can send the client a request through its `Peer` (`mcp::peer`) and wait for the answer on the same stdin, without a timeout: meanwhile a `ping` is answered, other requests are queued (16 at most) and served after the call, and `notifications/cancelled` for the call ends the wait with no response. Every line gets at most one answer; a line over 10 MiB is discarded whole.

**commands** reaches `mcp` to start the MCP server (`serve`) and to run a tool's CLI twin (`mcp::twin`): `trurlic apply <file>` and `trurlic status` find the store as a call does and run the tool's own spec parse and handler without a client (`mcp::twin`), and print through one path (`commands::answer`) a line per item for a terminal or, with `--json`, the text the call returns, every refusal included, a store discovery cannot find among them; a batch file that cannot be read is `invalid_argument`, as one that is not JSON; every other handler reads and writes the graph through `Store`. `check` compiles the `[quality]` patterns, which no read does, and fails on one that does not compile. `migrate` asks `git` which graph files the project's git tracks, and `check` what git says of where the graph sits (`commands/placement.rs`), and each hands the answer to the store as data: the store asks git nothing about the project's repository, and runs it only in the graph's own.

**git** runs `git -C <dir>` with stdin closed (or carrying the input of an `update-index` in the graph's own repository) and clears every variable through which a caller can point git at another repository, index, work tree or configuration (`git::CLEARED`): trurlic runs inside a project's git hooks, where git exports `GIT_DIR` and `GIT_INDEX_FILE`. A missing binary is `Error::GitMissing`, a failed command `Error::GitFailed` with git's stderr. "No work tree" is a typed answer (`toplevel` returns `None`), never a parsed message: git exits 128 for it as for every fatal error, so the runner asks git only when a `.git` is at or above the directory (`git::dot_git`), and answers `None` without git otherwise, or when `--is-inside-work-tree` says `false` (a git directory, a bare repository). It holds only the questions a caller asks; no libgit2.

**git::graph** is the one module that runs git inside a graph directory, in the graph's own repository (`.trurlic/.git`), which only trurlic writes; discovery and the placement facts never do. Every call but `init` names the repository and its work tree (`--git-dir`, `--work-tree`), so git discovers nothing and a missing `.git` is git's error, never the project's repository answering. It reads no system or user configuration (`GIT_CONFIG_NOSYSTEM`, `GIT_CONFIG_GLOBAL` set to the empty file): the user's settings say how they use git in their projects, and no list of overrides could shut out all of them. The repository's own configuration, which that cannot shut out, is overridden with `-c` where a key runs code or changes bytes (`core.hooksPath` to the empty file, `core.fsmonitor`, `core.excludesFile` and `core.attributesFile`, read from `$XDG_CONFIG_HOME` when unset, `core.autocrlf`, `core.fileMode`, `commit.gpgSign`) and `core.fsync=committed` puts objects and refs on disk before the journal that names a write's blobs is written and before the journal that would redo the commit is deleted, with `core.fsyncMethod=batch` (git 2.37; an older git warns and fsyncs each object) flushing the loose objects of one object transaction with one hardware flush before they get their names. The identity is set in the environment, which beats every configuration key (`trurlic <trurlic@trurlic.invalid>` as author and committer), and `GIT_AUTHOR_DATE`/`GIT_COMMITTER_DATE` are removed, so the dates are git's clock. What reaches the index and the object store is `git::graph::index`'s. A write's blobs are written before its commit point from the files it staged in `.state/tmp/`: one `update-index -z --add --stdin` on a scratch index (`GIT_INDEX_FILE` in `.state/tmp/`, `.state/tmp/` its work tree), one object transaction, its ids read back with `ls-files --stage`; neither the repository's index nor its work tree is touched. The history commit's index is then set from those ids with `update-index -z --index-info` (a removal is mode 0 at the null name), so the commit holds the bytes the write staged. A `hand edit` commit, and the first commit of a repository, stage the files as they are on disk with one `update-index -z --add --remove --stdin` over every path, the first commit's thousands included, in one object transaction. `update-index` converts what the attributes ask, so the repository's `info/attributes`, which beats every `.gitattributes`, unsets every converting attribute, is written at creation and checked, and written again, before every staging and every write of blobs, and `git status` and `git commit` read through it too. A symlinked node file alone is staged through `hash-object --no-filters`, as the bytes a load reads through it. `git hash-object -w` opens no object transaction, so it flushes each object on its own: it writes no write's blobs. `git init` uses no template (`--template=`) and `--initial-branch=main`; the commit is `git commit --no-verify --cleanup=verbatim -m`, and a commit git refuses for having nothing to commit, which `diff --cached --quiet` confirms, is no failure. `status` runs with `--no-optional-locks`, so it writes no refreshed index and a read can ask it.

**code** is pure: its input is a file's kind and bytes, or the facts a shell gathered, and its output is values; it names no file system, process, environment or clock (`code::tests` holds its sources to that). A file's index (`code::index`) is a function of its kind and bytes alone: its definitions, each with its path of names from the outermost container, its kind (`code/kinds.rs`: a Rust item's by its node and container, a `fn` of an `impl` or trait a method; a key, a target or a heading for the lexical resolvers), whether its file states it is test code (`code/rust/marks.rs`: an attribute whose path ends in `test`, or `bench`, or a `cfg` that holds only under `test`, outer or inner, on it or on a container), its visibility (its own modifier; a variant's, a variant field's and a trait member's are their enum's or trait's; none for a trait impl and its members, a type a macro invocation defines, and every lexical definition), its byte and line span and its span hash, and for Rust the `macro_rules!` macros that can define a type and the invocations in item position. What depends on other files is a second step over the tree's indexes: a Rust file is test code whole under its crate's `tests/` directory or when a test module, or a test file, declares it (`code/roles.rs`), which `CodeFacts::definitions` folds into each definition's role; and the macro expansion (`code/expand.rs`): an invocation sees its crate's macros (the nearest `Cargo.toml` above it) and its workspace's `#[macro_export]` ones, and pyo3's `create_exception!`/`import_exception!` by argument position (`FOREIGN_TYPE_MACROS`). Rust is parsed by tree-sitter (`code/syntax.rs`, `code/rust.rs`; a second grammar is one file beside `rust.rs` and one row of `FileKind`), within a budget of parser steps and of bytes the lexer scans, both per byte of the file; an item an invocation spells in its tokens (`define! { struct Name }`, `proptest! { fn case() }`) is a definition by the lexical rule of `code/rust/macros.rs`. TOML (the `toml` crate's spans), JSON (a scanner of its own), Makefiles and Markdown have lexical resolvers. A symbol (`code/symbol.rs`) is a `::`-separated path of names from the outermost container, a trait impl a `<Trait>` segment (`Config::<Display>::fmt`); it names each definition whose path ends with it, a trait segment it leaves out skipped but never the definition's last, and among several the one whose whole path it is. `CodeFacts::resolve` gives each anchor one `Resolution`: `Resolved` (a file, a directory, or a symbol's span and hash), `FileMissing`, `SymbolMissing`, `Ambiguous(n)`, `SymbolOnDirectory`, `NoResolver`, `Unindexable` (the read or index fault) or `Malformed` (a symbol out of the grammar). A span hash is `t1:` and the BLAKE3 of the span's tree-sitter leaf tokens, comments dropped, or of a lexical span's whitespace-normalized text; `t1` names the normalization.

**sources** gathers the facts `code` is pure over, for `status` and `check` alike (`sources::resolve_anchors`): it walks the code root for every Rust file and `Cargo.toml`, passing over every entry whose name starts with `.`, every directory at the top of another work tree (one holding `.git`), every directory tagged `CACHEDIR.TAG` and every symlinked directory, and spawns no process; it looks at each anchor's path wherever it is. A file is read in one bounded read, refused unopened when it is no regular file and past `MAX_SOURCE_FILE_BYTES` (4 MiB); one that vanishes between the walk and the read is absent. Files are indexed in parallel, from the cache when it holds their key, and the misses are written to the cache after the call's own work, under the exclusive lock only when it is free (`Store::try_lock`): a busy lock skips the write.

Trurlic makes no LLM calls. Design work happens in the agent that calls the MCP tools.

### Store Internals

Graph on disk (format 0.5): `.trurlic/project.toml` (`format_version`, `name`, `description`, `placement = "tracked" | "shared"`, and an optional `[quality]` table, below), `components/<name>.toml` (`description`, `connects_to`) and `decisions/<name>.toml` (`component`, `choice`, `reason`, `alternatives`, `tags`, `status = "proposed" | "accepted"`, `accepted_via`, `origin`, `created`, `anchors = [{file, symbol?}]`, `depends_on`, and an `[accepted_text]` table, the accepted `choice`, `reason`, `alternatives` and `accepted_via`, while a revision of an accepted decision is proposed). The file stem is the node's name, kebab-case and at most 128 bytes; no file holds it, and a stem is unique across node kinds. Each edge lives in the file of its source; `project` is the component of the project-wide decisions and has no file. There is no index, no pattern, no history and no hash in the node files; a shared graph's history is a git repository of its own (History, below). `.trurlic/.state/` holds the lock file, temp files, the commit journal (`txn.toml`) and the code index's cache (`symbols/`); it is never committed.

Types (`store/schema.rs`) refuse every key they do not know and every value they cannot hold: `accepted_via` on a proposed decision, `accepted_text` on an accepted one, an anchor path that is absolute, holds `..`, a backslash, an empty or `.` segment.

Load and validation: a load (`store/load.rs`) fails only when a file cannot be read as its type: it is no regular file once its symlinks are followed (`Error::NotAFile`, refused before it is opened, so a FIFO never blocks a reader), it cannot be read, it is over 1 MiB (refused before it is parsed), it is not TOML, or its type refuses it; the error names the file. Every entry of `components/` and `decisions/` whose name ends in `.toml` is a node file, as the history's pathspecs match them: one whose name is not UTF-8 is `Error::NodeFileName`, and none is skipped; each one's metadata is asked, its symlinks followed, in the parallel read of it, before it is opened. The journal, a staged file a replay reads, the lock file and the graph repository's `info/attributes` are refused alike when they are no regular file. Everything a loaded graph can hold but should not is an issue `ProjectState::validate` reports with the file it is in: a stem that is not kebab-case, is over 128 bytes or is `project`, a stem a component and a decision share, a component, `connects_to` or `depends_on` that names no node of its kind, a self-edge, a `depends_on` cycle, and a text that breaks `store::text` (`invalid_choice`, `invalid_reason`, `invalid_alternative`, `invalid_tag`, `invalid_origin`, `invalid_description`, the accepted text a revision keeps included). An anchor's `file` and `symbol` meet the character rule as part of their type, a load failure like every other anchor fault. `check` fails on an issue; `status` and the reads still answer.

Canonical form (`store/canonical.rs`): the one serializer of node files and `project.toml`. Keys in a fixed order per file type; sets (tags, edges, anchors, a pattern's fields) sorted, one element per line with a trailing comma, so two branches that add elements at different places merge; an empty set or list, an absent limit, a `false` flag and a default `[quality]` left out; a string with a line break as a `"""` string; a `[quality]` pattern as a `'...'` literal string unless it holds a `'` or a control character other than tab. The form is Trurlic's, not the TOML library's printer. Every load notes the files whose bytes are not canonical, comparing as it writes without allocating; `check` warns about each and `trurlic fmt` rewrites exactly those in one commit.

Commits: write the canonical text and parse it back in memory, refused unless a load reads it as the value written (within 1 MiB, `Error::CanonicalTooLarge`, which `apply` turns into the refusal `file_too_large` naming the op that last changed the file, and `fmt` reports naming the file; one record at every surface limit stays under the cap, its accepted text included, `store/limits.rs`) → under `shared`, the history step before the commit point (below) → stage each file in `.state/tmp/` under a per-process name and flush it, the files of one commit in parallel → under `shared`, write the staged files to the graph's repository as blobs → write and flush the journal, which names every staged file, its target and the BLAKE3 of its bytes, and under `shared` the history step: the message, the commit it goes on and each file's blob id: the commit point → rename the staged files into place, then remove deleted files, flush the directories → under `shared`, the history commit, its index set from the blob ids → delete the journal and flush `.state/`, so a journal that names a step is on disk exactly while its write is unfinished (one that came back after a power loss would remove files re-created since). A journal names only the steps still to do: a history commit that fails once the files are in place replaces it, flushed, with a journal of the history step alone, so no later read or write renames or removes again; a finished write whose journal cannot be deleted leaves one that names no step, which the next opener deletes. After the journal a failure returns `WritePending`; the write is not rolled back.

History (`store/history.rs`): under `tracked` the project's git holds the history and trurlic never commits. Under `shared` the graph directory is a git repository of its own, `.trurlic/.git`, with `/.state/` in its `info/exclude`: `trurlic init` makes it and commits `project.toml` as `init`, and `migrate` to `shared` makes it when there is none, its commit then the repository's first. Each write is one commit whose subject names the tool (`store::Tool`: `init`, `fmt`, `migrate`, `apply`) and whose trailers carry `Origin:` and `Session:` when the write has them (`store::CommitMessage`, each one line, checked by `store::text`); a writer passes it as data (`Writer::commit`). Before the commit point the history step makes a repository that is gone again, with a warning, refuses a leftover `.git/index.lock` (`Error::GraphIndexLocked`, nothing written), and commits as `hand edit` every graph file (`project.toml`, `components/*.toml`, `decisions/*.toml`, one level deep: never `.state/`, never another file) the last commit does not hold as it is on disk, modified, deleted or new, so the write's commit holds the write alone; `fmt` with nothing to rewrite does this step alone. Then the write's staged files are written to the repository as blobs, and the journal carries the history step (`history::HistoryStep`): the message, the branch's commit the write's goes on, each file's blob id and the removals. After the renames the index is set from that step and committed, so the commit holds the bytes the write staged whatever the files hold by then: a hand edit made between a stopped write and its finishing stays uncommitted and lands in the next `hand edit` commit. A repository with no commit yet stages every other graph file as it is on disk, so its first commit holds the whole graph. An opener that finishes a stopped write first looks for its commit: the first commit after the step's parent on the branch's first-parent line, when its tree holds the step's blobs and none of its removed files, is the write's (made before the stop, reworded, amended, packed or followed by a commit by hand since), and none is made again, so finishing a write is idempotent. A blob the repository lost since (a `gc --prune=now`, a repository made again) is staged from the file on disk, with a warning. A missing `git` refuses the write before its commit point. `Store::history_findings` (for `check` and `status`) reports, under `shared` only, a missing repository, a leftover index lock (an error: it refuses every write) and the uncommitted graph files, asking git without writing to the repository.

Recovery: a leftover journal is applied, its history commit made, then leftover temp files removed, only under the exclusive lock: by every write before it loads, and by every read that finds either one under the shared lock. A read whose recovery cannot make the history commit (git refuses it) warns that the files are in place and the commit waits (`journal::Replayed`), and loads the graph, whose files are whole; the journal stays, narrowed to the history step, and every writer is refused with `WritePending` until the commit can be made.

Timestamps: `store::Timestamp`, a UTC instant to the nanosecond, written as an RFC 3339 string in the form 0.3 releases wrote (`2025-06-01T10:30:00Z`, a fraction of 0, 3, 6 or 9 digits), so a load and a write give back the same bytes. `Timestamp::now` is the crate's one clock read; the dates of a history commit are read by the `git` process, never by trurlic.

Format version: `project.toml` states `format_version`, `MAJOR.MINOR.PATCH` and independent of the crate's version (`store::FormatVersion`, `FORMAT_VERSION` in `store/schema.rs`). The check has one home, `store/version.rs`: every read and every write refuses another format before it recovers anything or parses a node file. A newer one says to upgrade trurlic, an older one the registry names to run `trurlic migrate`, a version the registry does not name, or one no chain of steps leads from, that no migration leads to this format (`Error::NoMigration`), and a version that does not parse is named with its file and its text. `store::migration` holds the registry, one step per format change from 0.1.0 on; `trurlic migrate` walks the chain from the store's version, reports every value a step drops and every fact the owner must be able to read after the fact (the placement and how it was told, a turned `constrains` edge, an anchor respelled or kept, a history count, a pattern with its edges and tags, a component's tags), reads the result as the current types, which refuse any key they do not know, and lands it in one journaled commit that writes each file whose canonical bytes change, `project.toml` first, and then removes each file the steps dropped (`graph.toml`, the patterns). A migration stopped before that rename leaves an old-format store with a journal, which only the next `migrate` finishes; once it has happened, the store is current and the next command of any kind finishes it.

The step from 0.4.1 to 0.5.0 (`store/migration/format_0_5.rs`): each edge of `graph.toml` moves into its source file, `A constrains B` becomes `B depends_on A`, and a turned edge that closes a `depends_on` cycle is refused (`Error::ConstrainsCycle`, naming the members); `code_refs` become `anchors` in the 0.5 symbol spelling where the old spelling's syntax settles one (`migration/format_0_5/anchors.rs`), else kept and reported; `attribution = "agent"` becomes `proposed`, `user` or none `accepted`; history is dropped and counted; patterns and component tags leave the graph for the report; a key the step does not map is a reported loss, never a refusal. `placement` is stated with `--placement` or read from git: `tracked` when git tracks every file of `.trurlic/`, `shared` when none, else `Error::PlacementUnknown`. Before the commit `migrate` copies the old store to a new `.trurlic-backup-<time>/` beside it with the report in `migration-report.txt`, all flushed, since what the graph loses lives on only there.

File locking: std `File::try_lock` (writers, exclusive) and `File::try_lock_shared` (readers) on `.state/lock`, polled with a 5 s timeout. `StoreLock` is a proof-of-lock type: every entry point that changes a file under `.trurlic/` takes `&StoreLock`, and a `Writer` owns one.

Writer protocol: every write to a current-format graph starts at `Store::begin_write` (`init` and `migrate` take the lock and commit through `commit_batch` themselves), which takes the exclusive file lock, checks the format, recovers, loads the graph from disk and returns a `Writer` that owns the lock and that graph. Every graph write is a `Writer` method (`apply`, `format`) that ends in `Writer::commit(writes, removes, &CommitMessage)`, so all validation runs against the graph loaded under the lock, each commit leaves the writer's graph equal to disk, and the placement the graph states decides its history. Dropping the writer releases the lock.

Apply (`store/apply/`): `Writer::apply(Batch)` is the one write of the graph, for the MCP tool and `trurlic apply` alike. Its ops (`record`, `revise`, `rename`, `merge`, `remove`, `add_component`, `revise_component`, `rename_component`, `remove_component`, at most 50) run in order on the writer's graph in place, each touched node's starting value kept in an undo record (`edit.rs`), and each op is checked against the graph the earlier ops left: names (grammar, `project`, taken across kinds), existence, the component and edge targets of what it adds, no self-edge, no `depends_on` cycle the batch began without (found from the node the op gave edges, members named), no-op revises (the value, and so the canonical bytes, unchanged), a list given whole and by `add_*`/`remove_*`, a removal of what the list lacks, the quality bar of each decision a record, revise or merge writes (below), and the cascades: a rename rewrites every edge to the node, a component's rename its decisions and connections, a remove is refused while decisions depend on it unless `repoint_to` names their target, a component's while in use, and a merge repoints edges and unions anchors, tags and edges into the survivor, whose text stays. The first fault refuses the batch, naming the op, the argument and the rule (`store::Refusal`); a batch's own fault (no op, its `origin`) names the argument alone. A verdict of the bar on one element of a list names the argument that brought it, by its index in the caller's list (`check::Sources`: `ops[3].add_tags[0]`), and one on what no single argument holds (a count of the whole list, a merge's union, an element the decision held before) names the decision's field without an index. Then the resulting graph is validated once under "no new errors", an issue a node had counting as known under the name the batch's renames and merges carried it to (`Edit::carry`; a removal ends a node's identity, and a node the batch makes under a name another node left carries none of its issues), a `depends_on` cycle the graph began with likewise under its members' carried names (`validate::carry_members`, the op's cycle rule included), and the files whose value changed go through one `Writer::commit` with `Tool::Apply` and the batch's origin. A recorded decision is `proposed` with the batch's origin and one `Timestamp::now` per batch; no op writes `accepted`, `accepted_via` or `accepted_text`; a revise of an accepted decision's text moves the old text, with its `accepted_via`, to `accepted_text` and proposes the new, and a revise back to it accepts it again. A refused batch, or a commit that fails before its commit point, leaves the writer's graph as it was.

Quality (`store/quality/`): two kinds of rule govern a decision's text and shape. What every file must hold to be read as written is `store::text`: no invisible, reordering or control character and no tool-call markup in any text, and each field's shape (a choice one non-blank line within 200 bytes, a reason of real text, an alternative one non-blank line within 1,000 bytes, a tag one within 128, an `origin` one within 200, a component's description any prose within 50,000), a validation issue `check` reports. The quality bar binds only a write: at least one alternative and one anchor, built in, and the project's `[quality]`: `reason_words = {min, max}`, `alternatives_max`, `alternative_words_max`, `anchors_max`, `require_origin`, and `patterns = [{pattern, fields, level, message}]`, regular expressions over `choice`, `reason`, `alternatives`, `tags`, `anchors` (as `file::symbol`) or the batch's `origin`, `level = "refuse" | "warn"`. The table is typed (`Quality`, `deny_unknown_fields`, every key optional, absent meaning the built-in rules alone), refused at load for a maximum of 0, a `min` over its `max`, a pattern out of bounds (`MAX_QUALITY_PATTERNS`, `MAX_PATTERN_BYTES`, a one-line message) or `warn` messages over `MAX_WARN_MESSAGES_BYTES` together, as JSON writes them, and holds its patterns as text: a read never compiles one. `Writer::apply` compiles them once per batch (`Bar::compile`, each within `MAX_PATTERN_COMPILED_BYTES`; one that fails is `Error::QualityPattern`, naming `project.toml`, its index and regex's message) and `Bar::judge` holds each decision an op writes to the text rules and the bar, in each field whose value the op changes (a record every field, a revise the fields it changed, a merge the anchors and tags the absorbed decision adds), limits first in the file's key order, then the patterns in their order; `origin` is judged once per batch, with `require_origin` when the batch records. The first rule broken refuses the op as `Rule::Text` or `Rule::Quality(QualityFault)`, whose `Limit` carries the measured value and the bound, in the rule's unit; a `warn` pattern's first match per op is a `store::Warning` in the result, of which each op lists `MAX_WARNINGS_PER_OP`. A field the op leaves as it is keeps what it held, so a graph below the bar loads, passes `check` and stays revisable. A word is a run of text between Unicode whitespace.

Code index cache (`store/symbols.rs`, `sources/cache.rs`): `.state/symbols/` holds one file per indexed file content, named by its key, the BLAKE3 of the file's kind, the span hash scheme, `code::INDEX_FORMAT` and its bytes, so an entry is never read under other rules and one graph's trees share entries by content; `code::index`'s fingerprint test makes a change to how a file is indexed raise `INDEX_FORMAT`. An entry is a line with the BLAKE3 of the rest, then the JSON of its key and the index; one that is no regular file, is over `MAX_SYMBOLS_ENTRY_BYTES`, or whose sum, key or JSON does not hold is a miss and is written again. A read holds no lock (each entry is written to a file of its own in the directory and renamed over its name, never through `.state/tmp/`, which belongs to the commit path); every write and removal is a `Store` method that takes `&StoreLock`, and is not flushed: the cache is never authoritative. A write removes any file that is no entry, and, when the directory holds more than twice the live set of the call and 256 besides, every entry outside it, so its growth needs no clock.

Readers: every read (`Store::load_state`) takes the shared lock, checks the format and loads the graph. A journal or a temp file seen under the shared lock was left by a writer that stopped, so the read takes the exclusive lock, finishes that commit and loads under it: no read sees half of a commit.

In-memory state: `ProjectState` holds `BTreeMap`s of `Component` and `Decision` by stem, the `Project`, and the files that are not in canonical form; the queries of `store/query.rs` walk the maps. It lives for one call.

Placement and discovery (`src/discovery.rs`): one function, `discover`, finds the graph for `serve` (on every tool call) and every CLI command that opens one, and returns a `Store` holding both roots: the graph directory, by its real path, and the code root, the tree the call comes from, which anchors resolve against (`ProjectState::code_root`), never the graph's real path. The walk goes up from the directory and never leaves the work tree it starts in. In each directory the `.trurlic` there comes first, a symlink of that name followed, so a clone or a copy outside the repository reaches the graph through one; its code root is the directory holding the symlink. A directory with no `.trurlic` whose `.git` is a file is the top of a linked worktree or a submodule: the walk stops, and the graph is the main worktree's when it states `shared` (`git worktree list`, read from the common dir, names the main worktree first), `StoreNotFound` under `tracked` or when the main worktree is the directory itself. A directory whose `.git` is a directory is the top of a main worktree or of a repository cloned inside another project's tree: a graph above it is not that repository's, and the walk stops with `StoreNotFound`. A tree with no git at all is walked to the root of the file system. A graph directory is passed through to the tree that holds it, its own `.git` being its history, no work tree. Git runs only at a linked worktree's top with no graph below it: a tree that holds its graph spawns no process (two metadata calls per directory), and a linked worktree of a shared graph spawns one. A `.trurlic` that leads to no directory (a dangling or looping symlink, a file) is a typed error that stops the walk. Under `tracked` every worktree carries its own graph; under `shared` one graph in the main worktree serves every linked worktree, and `.state/`, the lock and the journal, belongs to the graph directory, so writers in every tree of one graph take one lock. `check` holds the placement to git (`ProjectState::placement_issues`, pure over the `PlacementFacts` `commands/placement.rs` gathers, by the rule the migration reads git's listing with): a tracked graph is in a work tree, git tracks a file of it and ignores none; a shared one is tracked by no git and, in a work tree, is the graph at the top of the main worktree, beside which no worktree carries another. `init` refuses a tracked graph outside a work tree or under an ignore rule, a shared one in a work tree anywhere but the top of a main worktree, and any graph in a linked worktree the main worktree's shared graph serves; it writes `.trurlic/.state/` to the `.gitignore` beside a tracked graph and `/.trurlic/` to the common dir's `info/exclude` for a shared one, whose own repository it makes first, so a missing `git` leaves no `.trurlic/` behind.

No state between calls: the MCP server holds the directory it was started in, and every tool call finds the store from there and loads it. A read tool runs on `Store::load_state`, a write tool on a `Writer`, so a hand edit, a `git checkout` or another process's commit is seen by the very next call. `serve` starts without a store or with one in another format, and each call is refused until it is fixed, naming `trurlic init`, `trurlic migrate`, or the file and text of a version that does not parse. `load_state` reads the node files in parallel, each in one bounded read; `make bench` times it.

### Key Invariants

1. `unsafe` is forbidden (`[lints.rust] unsafe_code = "forbid"` in Cargo.toml): no `#[expect]` can lift it.
2. Invariants a tool can check are lints, in Cargo.toml's `[lints]` and `clippy.toml`, and `tests/lints.rs` proves each refuses a seeded violation: no `unwrap`, `expect`, `panic!`, `todo!`, `unimplemented!` or `dbg!` outside tests; no `HashMap`/`HashSet`; stdout and stderr only through `console` (and the MCP transport, which owns stdout under `serve`); the clock only through `Timestamp::now` (a history commit's dates are the `git` child's, which no lint of this crate sees). An exception is an `#[expect(lint, reason = "...")]` at its site; `#[allow]` is refused.
3. A write adds no issue: the graph it commits has no issue, matched on kind and subject, that the graph it loaded lacked (`validate::introduced`), a subject read under the names the write's renames and merges gave its nodes. `apply` validates its resulting graph once per batch, and the graph it began with only when that one has an issue; `fmt` commits only canonical text that reads back as the value loaded, so the graph it commits is the one it loaded. A batch is all or nothing: one commit, or no file written.
4. Atomic commits: canonical text read back in memory → flushed temp files → under `shared`, their blobs → flushed journal (the commit point) → renames → directory flushes → under `shared`, the history commit from the blobs. Recovery rolls a journal forward under the exclusive lock, its history commit included, makes that commit at most once, and runs no file step of a journal a failed history commit narrowed.
5. History: under `shared` every write is one commit in the graph's own repository, holding the bytes the write staged, after one `hand edit` commit of whatever a hand edit left, as the fixed identity, whatever the caller's environment or configuration (`tests/integration/history.rs`); under `tracked` trurlic never commits.
6. File locking prevents concurrent mutations from CLI and MCP processes.
7. What a call returns is a function of the files on disk: no process holds graph state between calls (`tests/integration/stdio.rs` sees a hand edit in the next call).
8. Node files are read only as their types, with `deny_unknown_fields`, after a read capped at `MAX_NODE_FILE_BYTES` (1 MiB), and written only in the canonical form: the types derive `Deserialize` and no `Serialize`, so no other serializer can write one.
9. Every dependency justified. No proc macros at runtime (serde derive, thiserror are compile-time).
10. Every MCP tool result fits `budget::MAX_TOOL_RESULT_BYTES` (24 KiB) and stays valid JSON; a cut is named in its `truncated` array, and a `status` section that leaves items out says how many and where the rest is. Every tool description fits 2,048 characters, and `tools/list` is the specs' own definitions, then the two reads that predate them (`mcp::tools` tests).
11. A panic while a request is handled is answered `-32603` and the server serves the next request: release builds unwind (`panic = "unwind"`), `mcp::Server::answer` is the one `catch_unwind`, and nothing outlives a request half-done (no graph is held; unwinding drops a writer's lock; every line is built before it is written). `tests/integration/server_failpoints.rs` panics under the shared lock, then a writer takes the lock and the server answers again.
12. The code index is pure and its cache never authoritative: `code` names no file system, process, environment or clock (`code::tests`), every source file it is handed is read by `sources` in one bounded read, and an entry of `.state/symbols/` that is unreadable, oversized, of another version or not what its key says is a miss (`sources/tests.rs`, `store/symbols.rs`).

### Trurlic

This project uses Trurlic for its own architectural decisions. Before a
task, read the decisions that constrain it; implement within them; record
the choices they leave open; check before committing.

```
1. read the decisions of the files you will edit: .trurlic/decisions/*.toml
   (grep their anchors), or get_decisions_for_file(path) and
   get_context(component) over MCP
2. implement within them
3. a choice no decision covers, or one a change makes stale: a batch file
   of ops, then trurlic apply <file> (or the apply tool): record, revise,
   rename, merge, remove; one batch per change, with an origin
4. trurlic check: no issue before committing
```

- When touching a second module, read that module's decisions too.
- `apply` holds each decision it writes to this repository's bar, `[quality]` in `.trurlic/project.toml`: a reason of 20 to 300 words, at most 5 alternatives of at most 50 words each, 1 to 10 anchors, ASCII prose, and an `origin` on every batch that records.
- A decision `apply` records is `proposed`; it stays proposed until the user accepts it. A choice the user made in this conversation is then set `accepted` by editing its file (`status = "accepted"`, no `accepted_via`) until `accept` lands; a revision of an accepted decision's text is proposed again, with the accepted text kept.
- When the task is to design something, discuss the choices with the user before implementing, and record each one they agree on.
- After implementation, re-read the decisions and check none was silently violated.

### Testing

Unit tests: pure functions, same file. Every module has exhaustive tests for its public contract. Every file type reads back from its canonical text as the value written.

Integration tests (`tests/integration/`): drive the built binary. `harness` spawns `trurlic serve` and speaks JSON-RPC over stdio, playing the client for the server's own requests too; `golden` compares output with `tests/integration/golden/` (`TRURLIC_UPDATE_GOLDEN=1` rewrites the files). Every tool in `tools/list` is called once. `stdio.rs` covers each protocol case: version negotiation, each malformed line (a line without `method` answered with `id: null`, during a server request too, `server_failpoints.rs`), an oversize line, an unknown tool, a server with no store or an old one. `apply.rs` holds the one write to its contract over both surfaces: one batch of every op kind writes the same bytes over MCP and from a file, a 50-op batch with one invalid op writes nothing and names it, the command reads stdin and refuses a file that holds no batch, `status --json` is the tool's text, every twin refusal, a failed discovery's included, is the call's refusal on stdout under `--json`, a batch file that cannot be read is `invalid_argument`, a `[quality]` table holds both surfaces alike, its warnings on stderr for a terminal, and `--section` takes exactly the tool's sections. `malformed_node.rs` has one test per shape a hand edit can break; `canonical_form.rs` holds `check` and `fmt` to a hand edit; `git_merge.rs` merges two branches of a tracked graph in a real git repository; `placement.rs` builds a main worktree, a linked worktree, a linked worktree nested in the main one and a symlinked clone with real git and runs `serve`, `status`, `check`, `init`, `apply` and contending writers in each, a repository inside a project's tree finding no graph, and finds the writes of all three in the one graph repository, three servers applying batches at once included; `history.rs` holds a shared graph's history to its rules: one commit per write after one of the hand edits, a write with `GIT_DIR` set elsewhere, under `tracked` no commit, a user configuration, an environment and a repository configuration set to break or redirect a commit, the findings of `check` and `status`, an index lock, a missing `git`, a stop at each step after the commit point, one commit per `apply` with its `Origin:`, a batch with removals stopped at each step of its commit, a write stopped with its hand edits staged, and a stopped write whose history commit holds its own bytes and removes no file twice while a hand edit and a re-created file wait for the next `hand edit` commit. `harness::Project::init` is a git repository with its tracked graph committed (`init_uncommitted` the same before the commit, `shared` a shared graph in no work tree, `graph` the graph directory), and every `trurlic` the harness runs, and the git it spawns, reads no user or system git configuration.

Specs: `mcp::spec` holds one table-driven test over an argument spec with every field kind, refusing each malformed shape with its field named, and a test of the result spec's schema and value. `store/apply/tests.rs` covers each op and each rule with the argument it names, the status rules, the cycle rule against the cycles a graph began with, the undo of a refused batch, and that only changed files are written; `store/apply/tests/quality.rs` holds the bar to its contract through `Writer::apply`: each built-in rule refusing with its name, field and measure, a verdict on an element naming the caller's argument in every list field and form, each `[quality]` key moving its limit, `require_origin`, a pattern matching only its fields at its level, the fields a revise and a merge are judged in, and a pattern that does not compile. `store/quality/` loads the shipped `examples/quality.toml` through the reader of every `project.toml`, compiles it and holds it to its own bar.

Failpoints: the `failpoints` cargo feature (test job only) makes `TRURLIC_FAILPOINT=<site>:<n>` act at the n-th hit of a named site in `src/store/failpoint.rs`: abort (or pause, with `TRURLIC_FAILPOINT_PAUSE`) at a `hit` (`commit.staged`, `history.blobs` with the blobs written and no journal, `commit.journaled`, `commit.applied` after each rename or removal, `commit.placed` with the files in place and the history commit not made, `history.staged` with an index set for a commit not made, the `hand edit` one before the commit point or the write's after it, `commit.narrowed` with a failed history commit's journal narrowed to it, `history.committed` before the journal is deleted, `commit.finished` after its deletion is flushed), return an injected I/O error at a `fail` (`commit.rename`, `commit.forget` at the deletion of a finished write's journal, `commit.forgotten` at the flush of that deletion), panic at a `panic` (`graph.loaded`, under the shared or the exclusive lock), and let the caller act at a `triggers` site (`mcp.server_request`, where a tool call sends the client an elicitation form instead of running). `make test` enables it.

Property: determinism (every read tool answers with the same bytes in two processes), graph validation catches all known violation classes, and every node of the corpus reads back from its canonical bytes, which are a fixpoint.

Code index: each resolver has unit tests of its constructs with their spans (`code/rust/tests.rs`, `code/toml.rs`, `code/json.rs`, `code/make.rs`, `code/markdown.rs`), the test attributes and `cfg` predicates (`code/rust/marks.rs`), the file rule of test code (`code/roles.rs`), the symbol grammar and its matching (`code/symbol.rs`), the macro expansion's crate and workspace rules (`code/expand.rs`), the parse budget against a lexer that rescans the file (`code/syntax.rs`), and a nesting past `MAX_NESTING` in each scanner. The per-construct fixture corpus (`tests/fixtures/code/`, its manifests named `Cargo.toml.fixture` so cargo takes no directory of it for a package; the test copies it with the names fixed) resolves one anchor per construct and per outcome through `sources` (`sources/tests.rs`) and states each of its definitions' kind, role and visibility, with a FIFO, a symlink loop, a file over the cap and bytes that are not UTF-8; there too a warm index answers as a cold one, an entry swapped for another key's is a miss and is replaced, and a busy lock skips the cache write. `store/symbols.rs` holds the cache's files to their contract.

Format fixtures (`tests/fixtures/formats/<version>/`): a graph written by the trurlic of each historical format; no release wrote 0.4.1, so its fixture is the 0.4.0 one through the 0.4.1 step, extended with what a 0.4.1 store can hold. Each one migrates to the current format, loads and passes `check` in a named test, its report and result pinned by a golden file. The step to 0.5 has a unit test per rule over the 0.4.1 fixture's tables, a check of the migrated fixture and of the seeded corpus written as 0.4.1 against what their old files say (`store/migration/mod.rs`), and `migrate.rs` reads the placement from real git repositories isolated from the user's configuration.

No test for the sake of coverage. Every test asserts a property someone could break.

Benchmarks (`benches/corpus.rs`, criterion, run locally with `make bench`; no CI job): over the seeded corpus (`trurlic::bench::Corpus`, crate-private in `store::corpus`, its draws from `store::seeded`, the one seeded source of the property tests too) at 50, 600 and 2000 decisions, `load_state`, validation, and, through `trurlic::bench::Server` in process, every read tool, each with the load every call makes; at 600 and 2000, a `fmt` of one file under `tracked`, under `shared`, and under `shared` after a hand edit, whose differences are what the history costs a write, and `apply` of a one-op and a fifty-op batch under each placement and under `tracked` with `examples/quality.toml`, whose patterns each batch compiles; `load_state` is timed with that table too; and the code index over this repository's `src/`, cold (its cache emptied before each run) and warm (`trurlic::bench::resolve_anchors`). The `bench` feature builds the corpus, that server and that entry point; release builds carry none of them.
